# ТЗ: локальный сервис маскирования данных — версия 1

Nov 15, 2026 · @Thomas

## 1. Назначение и как работать с этим ТЗ

Сервис маскирует персональные и чувствительные данные в таблицах XLSX/CSV полностью на локальной машине, без интернета. Главный сценарий: перед тем как отдать выборку клиентских данных облачной модели (например, для построения дашборда), заменить ФИО, телефоны, документы и т.п. на псевдонимы так, чтобы структура данных осталась рабочей. Потом результат можно размаскировать обратно у себя на машине.

Приложение — локальный веб-сервер на Python, интерфейс открывается в браузере по адресу `127.0.0.1`. Позже его планируется завернуть в десктоп (Tauri), поэтому фронтенд должен быть статической сборкой без зависимости от сервера в интернете.

**Правила для Claude Code:**

1. Работай строго по этапам из раздела 12. Этап считается законченным, когда все его тесты зелёные и выполнен коммит.
2. Не добавляй зависимости, которые обращаются к сети во время работы приложения (телеметрия, CDN, загрузка моделей, проверка обновлений).
3. Никогда не пиши значения ячеек в логи, сообщения об ошибках и отчёты. Только типы, количества, имена колонок и листов.
4. В репозитории только синтетические тестовые данные (генерируются Faker `ru_RU`). Реальных данных в репозитории быть не должно.
5. Если требование неясно или противоречит другому, остановись и спроси, а не додумывай.
6. Код пиши так, чтобы в этапе 2 (DOCX и NER-модель) новые форматы и распознаватели добавлялись без переписывания ядра: через интерфейсы из разделов 7 и 8.

## 2. Рамки версии 1

Версия 1 — табличные данные без ML-моделей. Распознавание строится на заголовках колонок, регулярных выражениях и контрольных суммах, а финальное решение всегда принимает человек.

**Входит в v1:**

- Загрузка `.xlsx` и `.csv` (в том числе CSV в кодировке Windows-1251 и с разделителем `;`).
- Предпросмотр листов, выбор строки заголовка, выбор колонок для маскирования.
- Автоподсказки: какие колонки похожи на персональные данные и почему.
- Меню категорий: что маскировать (персональные, финансовые, коммерческие данные).
- Способы маскирования: псевдоним, фейк, метка, частичное скрытие, хеш, удаление, сдвиг и обобщение дат, масштабирование и шум для чисел.
- Поиск структурированных ПДн (телефон, email, ИНН и т.п.) внутри свободного текста в ячейках, плюс пользовательский словарь слов, которые маскируются всегда (название клиента, продукта).
- Сохранение форматирования XLSX и типов данных (число остаётся числом, дата датой).
- Очистка метаданных и скрытых мест утечки в XLSX (см. раздел 7).
- Зашифрованная таблица соответствий и размаскировка файлов XLSX, CSV, TXT, MD, HTML, JSON.
- Отчёт о маскировании без самих данных и простой CLI на том же ядре (раздел 10).

**Вне рамок v1 (не делать, но не мешать добавить позже):**

- DOCX и PDF.
- NER-модели и локальные LLM, а значит, поиск имён и адресов внутри свободного текста. Интерфейс должен честно предупреждать об этом.
- Старый формат `.xls`, файлы `.xlsm` с макросами, Google Sheets.
- Хук для Claude Code, десктопная упаковка, несколько пользователей, авторизация.
- Распознавание вариантов одного имени («Иванов Иван Иванович» и «Иванов И.И.» считаются разными значениями).

## 3. Глоссарий

| Термин | Что значит |
| --- | --- |
| ПДн | Персональные данные: любая информация, по которой можно определить человека (ФИО, телефон, СНИЛС…) |
| Распознаватель (detector) | Код, который находит в тексте данные определённого типа и возвращает их позиции |
| Маскировщик (masker) | Код, который заменяет найденное значение выбранным способом |
| Псевдонимизация | Замена, при которой одно и то же исходное значение везде превращается в один и тот же псевдоним (`Иванов → Клиент_017`) |
| Согласованность | Свойство «одинаковое → одинаковое» в пределах файла или проекта; нужно, чтобы не ломались группировки и связи между таблицами |
| Таблица соответствий (mapping) | Словарь «псевдоним → исходное значение»; хранится только в зашифрованном виде |
| Нормализация | Приведение значения к единому виду перед сравнением (`8 (912) 123-45-67` и `+79121234567` → одно и то же) |
| Контрольная сумма | Цифра (или цифры) номера, вычисляемая из остальных; позволяет отличить настоящий ИНН от случайных 12 цифр |
| Сессия | Один запуск сервера; временные файлы сессии удаляются при выходе |
| Проект | Именованный набор запусков с одной таблицей соответствий, чтобы псевдонимы совпадали в разных файлах одного клиента |

## 4. Офлайн и безопасность

Это требования с наивысшим приоритетом: нарушение любого из них — блокирующий дефект. Каждое проверяется автотестом (раздел 11).

**Сеть**

1. Сервер слушает только `127.0.0.1`. Запуск на `0.0.0.0` или другом адресе запрещён даже через настройки. Порт по умолчанию случайный свободный, можно задать флагом `--port`.
2. При старте генерируется случайный токен (32 байта, `secrets.token_urlsafe`). Браузер открывается по ссылке `http://127.0.0.1:<port>/?token=<токен>`. Сервер обменивает его на cookie `HttpOnly; SameSite=Strict` и убирает из адресной строки. Любой запрос к `/api/*` без верного токена → `401`. Зачем: иначе любой открытый в браузере сайт может отправить запрос на localhost.
3. Проверка заголовка `Host`: разрешены только `127.0.0.1:<port>` и `localhost:<port>`, иначе `400`. Зачем: защита от DNS rebinding (атака, при которой чужой домен подменяется на 127.0.0.1).
4. CORS выключен (никаких `Access-Control-Allow-*`). Заголовок `Content-Security-Policy: default-src 'self'; connect-src 'self'; img-src 'self' data:` на всех страницах.
5. Фронтенд не загружает ничего извне: ни шрифтов Google, ни CDN, ни аналитики. Всё лежит в сборке.
6. Никакой телеметрии и проверки обновлений. При старте процесс выставляет `HF_HUB_OFFLINE=1`, `TRANSFORMERS_OFFLINE=1`, `DO_NOT_TRACK=1` — задел на этап 2.

**Данные на диске**

1. Загруженные файлы и результаты хранятся в временной папке сессии (права `0700`). Папка удаляется при штатном выходе, по кнопке «Очистить сессию» и при следующем запуске, если прошлый завершился аварийно.
2. Таблица соответствий никогда не пишется на диск в открытом виде. Пароль не сохраняется нигде (формат шифрования — в разделе 9).
3. Логи содержат только техническую информацию: события, имена листов и колонок, количества, время. Исключения логируются без значений переменных. Имена загруженных файлов тоже могут содержать ПДн («Договор\_Иванов.xlsx»), поэтому в логах только `file_id`.
4. Имя выходного файла по умолчанию исходное + `_masked`, но интерфейс предлагает переименовать и предупреждает, если в имени найдены ПДн.

**Честность перед пользователем**

- На экране результата всегда видно предупреждение: имена и адреса внутри свободного текста в v1 не ищутся, результат нужно просмотреть.
- Необратимые способы (метка, частичное скрытие, удаление, обобщение, шум) помечены в интерфейсе значком «не восстанавливается».

## 5. Стек и структура проекта

Бэкенд на Python + FastAPI, фронтенд на React + TypeScript, собранный в статику и раздаваемый тем же FastAPI. Один процесс, одна команда запуска.

| Часть | Выбор | Зачем |
| --- | --- | --- |
| Язык | Python 3.11+ | Всё ML для этапа 2 (GLiNER, Natasha) на Python |
| Пакеты | `uv` + `pyproject.toml`, фиксация версий в `uv.lock` | Воспроизводимая установка |
| Веб-сервер | FastAPI + uvicorn | Простой, типизированный API через Pydantic |
| XLSX | `openpyxl` | Меняет значения ячеек, сохраняя стили, ширины, объединения, формулы. **pandas для записи не использовать** — он теряет форматирование |
| CSV | стандартный `csv` + `charset-normalizer` | Определение кодировки (UTF-8 / Windows-1251) |
| Фейковые данные | `Faker` с локалью `ru_RU` | Работает офлайн |
| Шифрование | `cryptography` (AES-GCM + scrypt) | Стандартная проверенная библиотека |
| Фронтенд | React + TypeScript + Vite | Статическая сборка потом без изменений встаёт в Tauri |
| Таблица в UI | TanStack Table + TanStack Virtual | Виртуальная прокрутка: рисует только видимые строки |
| Стили | Tailwind CSS (собирается локально) | Без внешних шрифтов и CDN |
| Тесты | `pytest`, `pytest-socket`, `hypothesis`; Vitest для фронта | `pytest-socket` запрещает сетевые соединения в тестах |
| Линтеры | `ruff`, `mypy --strict` для `core/` | — |

**Структура репозитория:**

```
datamask/
  CLAUDE.md                 # краткие правила для Claude Code (см. раздел 1)
  SPEC.md                   # это ТЗ
  README.md                 # установка и запуск простыми словами
  pyproject.toml
  scripts/
    run.sh / run.ps1        # сборка фронта (если нужно) + запуск
    make_fixtures.py        # генерация синтетических тестовых файлов
  backend/datamask/
    main.py                 # точка входа: порт, токен, открытие браузера
    security.py             # токен, проверка Host, CSP-заголовки
    api/                    # роуты FastAPI, Pydantic-схемы
    core/
      models.py             # Span, Detection, ColumnConfig, MaskConfig
      session.py            # временная папка, файлы, задачи
      pipeline.py           # чтение → распознавание → маскирование → запись
    formats/                # адаптеры форматов (интерфейс в разделе 7)
      base.py, xlsx.py, csv.py, text.py
    detectors/              # распознаватели (интерфейс в разделе 8)
      base.py, regex_ru.py, validators.py, headers.py, suggest.py
    maskers/                # способы маскирования (раздел 9)
      base.py, pseudonym.py, fake.py, label.py, partial.py, hash.py, dates.py, numbers.py
    mapping/                # таблица соответствий, шифрование, размаскировка
      store.py, crypto.py, unmask.py
    report.py               # отчёт без данных
  backend/tests/
    fixtures/               # только сгенерированные файлы
  frontend/
    src/ (pages/, components/, api/)
```

Ключевое правило архитектуры: `core/`, `detectors/` и `maskers/` ничего не знают о форматах файлов и об HTTP. Форматы превращают файл в набор ячеек/фрагментов текста, ядро работает с ними. Тогда DOCX в этапе 2 — это один новый файл в `formats/`, а NER — один новый файл в `detectors/`.

## 6. Пользовательский сценарий и экраны

Основной путь занимает пять шагов: загрузил → проверил подсказки → настроил колонки → посмотрел «до/после» → скачал. Интерфейс на русском, тёмная и светлая темы по системной настройке.

**Экран 1. Загрузка**

- Область drag & drop + кнопка «Выбрать файл». Принимает `.xlsx`, `.csv`; остальное отклоняется с понятным сообщением (для `.xls`: «пересохраните в .xlsx»).
- Лимит 50 МБ (настраивается).
- Выбор проекта: «Без проекта (только этот файл)» или один из ранее созданных проектов. Проект нужен, чтобы псевдонимы совпадали в разных файлах одного клиента.
- Для CSV — автоопределённые кодировка и разделитель с возможностью поменять.

**Экран 2. Настройка маскирования (главный)**

- Вкладки листов. Скрытые листы показываются с пометкой «скрытый» — в них тоже бывают данные.
- Таблица предпросмотра: первые 200 строк, виртуальная прокрутка, закреплённая строка заголовка. Скрытые колонки показаны приглушёнными.
- Переключатель «Строка заголовка: N» (по умолчанию определяется автоматически: первая строка, в которой больше половины ячеек — непустые строки). Строки выше заголовка (шапка отчёта) проверяются как свободный текст.
- В шапке каждой колонки:
  - выпадающий список **типа**: «Не маскировать», типы из раздела 8, «Свободный текст»;
  - выпадающий список **способа** (только способы, допустимые для типа, раздел 9);
  - значок подсказки с уверенностью и причиной при наведении: «Телефон, 94%: заголовок ‘Тел.’, 47 из 50 значений — телефоны».
- Колонки, выбранные для маскирования, подсвечены цветом. Для «Свободного текста» найденные фрагменты подсвечены внутри ячеек.
- Боковая панель **«Что маскировать»** (меню категорий). Три группы с чекбоксами, внутри каждой — типы:
  - Персональные данные (вкл. по умолчанию): ФИО, телефон, email, адрес, дата рождения, паспорт, СНИЛС, ИНН физлица;
  - Финансовые (вкл.): номер карты, расчётный счёт;
  - Коммерческие (выкл.): название организации, ИНН юрлица, ОГРН, суммы.
- Категории влияют на автоподсказки и на поиск в свободном тексте. Ручной выбор в шапке колонки всегда важнее категорий.
- Кнопки «Принять все подсказки», «Сбросить», «Сохранить как шаблон». Шаблон — набор правил «заголовок → тип + способ», применяется к файлам той же структуры.
- Предупреждения над таблицей: скрытые листы/колонки, сводные таблицы, примечания, формулы в маскируемых колонках (см. раздел 7).

**Экран 3. Проверка «до/после»**

- Две таблицы рядом (или переключатель): первые 50 строк исходника и те же строки после маскирования. Изменённые ячейки подсвечены.
- Сводка: сколько значений заменено по каждому типу, сколько уникальных, сколько ячеек пропущено (например, формулы).
- Поле пароля для таблицы соответствий (с повтором; минимум 10 символов) или чекбокс «Не сохранять таблицу соответствий (размаскировка будет невозможна)». Для проекта — пароль проекта.
- Кнопка «Замаскировать» запускает фоновую задачу с прогресс-баром.

**Экран 4. Результат**

- Скачать: замаскированный файл; таблицу соответствий (`.dmmap`, зашифрована); отчёт (`.json` и `.html`).
- Постоянное предупреждение о свободном тексте (раздел 4).
- Кнопки «Маскировать ещё файл» и «Очистить сессию».

**Экран 5. Размаскировка**

- Загрузить файл (XLSX, CSV, TXT, MD, HTML, JSON) + таблицу соответствий (или выбрать проект) + пароль.
- Предпросмотр: сколько псевдонимов найдено и будет заменено. Скачать восстановленный файл.
- Сценарий: Claude сделал дашборд (HTML) по замаскированным данным → загружаешь его сюда → получаешь дашборд с настоящими именами локально.

**Экран 6. Проекты** — список проектов (имя, дата, число записей), создать, удалить (с подтверждением в интерфейсе, не через `confirm()` браузера). Проекты хранятся в папке данных приложения (`~/Library/Application Support/datamask` на macOS, `%APPDATA%\datamask` на Windows) только в зашифрованном виде.

## 7. Работа с файлами XLSX и CSV

Исходный файл никогда не изменяется: результат — новая копия, в которой меняются только значения нужных ячеек, а всё остальное (стили, ширины, формулы в немаскируемых колонках, фильтры, закреплённые области) остаётся как было.

**Интерфейс адаптера формата** (через него в этапе 2 подключается DOCX):

```python
class FormatAdapter(Protocol):
    extensions: tuple[str, ...]
    def open(self, path: Path, options: OpenOptions) -> Document: ...
    def sheets(self, doc: Document) -> list[SheetInfo]: ...          # для CSV/TXT — один лист
    def preview(self, doc, sheet: str, header_row: int, limit: int) -> Preview: ...
    def iter_cells(self, doc, sheet: str) -> Iterator[CellRef]: ...  # адрес + значение + тип
    def iter_text_fragments(self, doc) -> Iterator[TextFragment]: ...  # имена листов, примечания, шапки
    def set_value(self, doc, ref: CellRef, value: CellValue) -> None: ...
    def risks(self, doc) -> list[Risk]: ...                          # скрытые листы, сводные и т.п.
    def sanitize(self, doc, policy: SanitizePolicy) -> list[str]: ...  # очистка метаданных
    def save(self, doc, path: Path) -> None: ...
```

**Скрытые места утечки в XLSX и что с ними делать:**

| Где прячутся данные | Поведение в v1 |
| --- | --- |
| Метаданные (автор, «кто изменил», компания, тема) | Очищать всегда |
| Примечания к ячейкам (и имя их автора) | По умолчанию удалять; опция «оставить и проверить как свободный текст» |
| Скрытые листы и колонки | Показывать в предпросмотре и обрабатывать как обычные; опция «удалить скрытые листы» |
| Сводные таблицы | Хранят **копию исходных данных** в кэше. Кэш удалять, предупреждать, что сводную нужно обновить в Excel |
| Кэшированные значения формул и диаграмм | Формулы сохранять, файл помечать на пересчёт при открытии (`fullCalcOnLoad`) |
| Формула в маскируемой колонке (`=A2&" "&B2`) | Не трогать формулу, посчитать в отчёте как «пропущено», предупредить. Если источники замаскированы, формула сама даст замаскированный результат |
| Имена листов и именованные диапазоны | Проверять распознавателями; при находке — предупреждение и предложение переименовать |
| Списки проверки данных, гиперссылки (`mailto:`), внешние ссылки на другие файлы | Гиперссылки в маскируемых ячейках удалять; внешние ссылки — предупреждение (в пути бывает имя пользователя) |
| Картинки (сканы, подписи) | Предупреждение с количеством; опция «удалить изображения» |

Если `openpyxl` не умеет какую-то из этих операций напрямую (например, удаление кэша сводных), допустима постобработка XLSX как ZIP-архива с XML внутри. Результат обязан открываться в Excel и LibreOffice без сообщения «файл повреждён».

**Типы значений:** число остаётся числом, дата — датой с тем же форматом отображения. Если способ маскирования даёт строку для числовой колонки (псевдоним для ИНН, записанного числом), это допустимо, но интерфейс показывает пометку «тип колонки изменится».

**CSV:**

- Кодировка: UTF-8 (с BOM и без), Windows-1251; определять автоматически, давать поменять. Разделитель: `,` `;` `\t` `|` через `csv.Sniffer`.
- На выходе сохранять ту же кодировку, разделитель, кавычки и переводы строк.
- Все значения CSV — строки. Не превращать `007` в `7` и не менять формат дат.

**Объёмы:** целевой размер — до 200 тыс. строк × 30 колонок. Предпросмотр читает файл в режиме `read_only` (быстро, без загрузки всего в память). Маскирование — в фоновой задаче с прогрессом.

## 8. Распознаватели и автоподсказки

Распознаватели делятся на **сильные** (формат + контрольная сумма или однозначный формат) и **слабые** (формат совпадает с чем-то безобидным). Сильные срабатывают сами по себе. Слабым нужен контекст: заголовок колонки или ключевое слово рядом в тексте («паспорт 4506 123456»).

**Интерфейс** (через него в этапе 2 подключается NER-модель):

```python
@dataclass(frozen=True)
class Span:
    start: int; end: int          # позиции символов в тексте
    entity: EntityType            # PERSON, PHONE, EMAIL, INN_PERSON, ...
    score: float                  # 0..1
    detector: str                 # какой распознаватель нашёл

class Detector(Protocol):
    name: str
    entities: set[EntityType]
    strength: Literal["strong", "weak"]
    def detect(self, text: str, ctx: DetectContext) -> list[Span]: ...
    def match_value(self, value: str) -> float: ...   # похожа ли целая ячейка на этот тип
```

Пересекающиеся находки разрешаются так: выигрывает больший `score`, при равенстве — более длинный фрагмент.

**Типы данных v1:**

| Тип | Категория | Сила | Как распознаётся значение |
| --- | --- | --- | --- |
| Email | Персональные | сильный | Стандартный шаблон, включая кириллические домены `.рф` |
| Телефон РФ | Персональные | сильный | `+7`/`8` + 10 цифр с любыми разделителями (пробел, `-`, `()`); нормализация к `+7XXXXXXXXXX` |
| ИНН физлица (12 цифр) | Персональные | сильный | Обе контрольные цифры: 11-я с весами `7,2,4,10,3,5,9,4,6,8`, 12-я с весами `3,7,2,4,10,3,5,9,4,6,8`; сумма mod 11 mod 10 |
| ИНН юрлица (10 цифр) | Коммерческие | сильный | Контрольная цифра с весами `2,4,10,3,5,9,4,6,8`; mod 11 mod 10 |
| СНИЛС | Персональные | сильный | 11 цифр (`123-456-789 01`); контрольное число по алгоритму ПФР (сумма цифр × веса 9…1, правила для 100/101 и mod 101) |
| Номер карты | Финансовые | сильный | 13–19 цифр + алгоритм Луна |
| ОГРН / ОГРНИП | Коммерческие | сильный | 13 цифр: первые 12 mod 11 mod 10; 15 цифр: первые 14 mod 13 mod 10 |
| Расчётный счёт | Финансовые | слабый | 20 цифр (без БИК контрольную сумму не проверить) |
| Паспорт РФ | Персональные | слабый | 4 + 6 цифр (`45 06 123456`) |
| Дата рождения | Персональные | слабый | Любая дата; только по заголовку |
| ФИО | Персональные | слабый | 1–3 слова кириллицей с заглавной буквы; уверенность растёт, если есть отчество (`-вич`, `-вна`, `-ична`) или имя из словаря имён Faker `ru_RU`; формат «Иванов И.И.» |
| Адрес | Персональные | слабый | Маркеры `г.`, `ул.`, `д.`, `кв.`, `пр-т`, индекс из 6 цифр |
| Организация | Коммерческие | слабый | `ООО`, `АО`, `ПАО`, `ИП` + название (в кавычках или без) |
| Сумма | Коммерческие | слабый | Число; только по заголовку |
| IP-адрес | Персональные | сильный | IPv4 с проверкой диапазонов октетов |
| Свой словарь | Коммерческие | сильный | Список слов, заданный пользователем в проекте (название клиента, продукта); регистр и ё/е не важны |

Для каждого типа есть словарь ключевых слов для заголовков (регистр не важен, лишние символы отбрасываются): «фио», «фамилия», «клиент», «сотрудник», «тел», «моб», «почта», «e-mail», «дата рождения», «д.р.», «адрес», «паспорт», «сумма», «выручка» и т.д., плюс английские варианты (`name`, `phone`, `email`, `address`). Словари лежат в одном YAML-файле, чтобы их легко было дополнять.

**Алгоритм автоподсказки для колонки:**

1. Взять до 200 непустых значений, равномерно по всей колонке (а не первые 200).
2. Для каждого типа посчитать `value_share` — долю значений, для которых `match_value ≥ 0.5`, и `header_hit` — совпал ли заголовок со словарём.
3. Сильный тип предлагается, если `value_share ≥ 0.8` или (`header_hit` и `value_share ≥ 0.3`).
4. Слабый тип предлагается только при `header_hit` и `value_share ≥ 0.5` (для «Дата рождения» и «Суммы» — достаточно того, что значения — даты/числа).
5. Если ни один тип не прошёл, но в текстах колонки сильные распознаватели нашли хотя бы одно совпадение и средняя длина значения > 30 символов, предлагается «Свободный текст».
6. Учитываются только типы из включённых категорий. Результат: тип, уверенность, способ по умолчанию и список причин для показа в интерфейсе.

Пороги вынесены в конфигурацию. В режиме «Свободный текст» работают сильные распознаватели, свой словарь и слабые с ключевым словом в пределах 30 символов слева («паспорт», «счёт», «р/с», «д.р.»).

## 9. Способы маскирования, согласованность и размаскировка

Способ по умолчанию для всех типов — псевдоним, потому что он сохраняет группировки и связи для дашбордов и обратим. Для дат по умолчанию — сдвиг, для сумм — «не маскировать», пока пользователь не включит категорию «Коммерческие».

| Способ | Пример | Обратим | Для каких типов |
| --- | --- | --- | --- |
| Псевдоним | `Иванов Иван → Персона_0017` | да | Все текстовые и идентификаторы |
| Фейк | `Иванов Иван → Смирнов Алексей` | да | ФИО, телефон, email, адрес, организация, ИНН, СНИЛС, карта |
| Хеш | `→ ФИО_a3f91c07e2` | да (через таблицу) | Все текстовые |
| Метка | `→ [ФИО]` | нет | Все |
| Частичное скрытие | `+7 *** ***-45-67`, `i***@m***.ru`, `**** 1234` | нет | Телефон, email, карта, счёт, ИНН, СНИЛС, паспорт |
| Удаление | `→ (пусто)` | нет | Все |
| Сдвиг дат | все даты на одно и то же случайное число дней (±365) | да | Дата рождения, любая дата |
| Обобщение дат | `14.03.1991 → 01.03.1991` или `→ 1991` | нет | Даты |
| Масштабирование | все числа колонки × секретный коэффициент (0,5–2,0) | да | Суммы: пропорции и тренды сохраняются |
| Шум | `±N%` к каждому значению | нет | Суммы, числа |

**Согласованность**

1. Таблица соответствий ведётся **по типу данных, а не по колонке**. Один и тот же человек в колонках «Менеджер» и «Ответственный» на разных листах получает один псевдоним. То же значение, найденное в свободном тексте, тоже получает тот же псевдоним.
2. Ключ сравнения — нормализованное значение: ФИО, адрес, организация — обрезать пробелы, схлопнуть повторы, нижний регистр, `ё → е`; телефон — `+7XXXXXXXXXX`; email — нижний регистр; ИНН, СНИЛС, карта, счёт, паспорт — только цифры.
3. Нумерация псевдонимов детерминирована: по порядку первого появления (лист → строка → колонка). В проекте нумерация продолжается, уже известные значения получают старые псевдонимы.
4. Область согласованности: «файл» (по умолчанию) или «проект».

**Детали способов**

- **Псевдоним**: формат `<Префикс>_<номер из 4+ цифр>`. Префиксы по умолчанию: `Персона`, `Телефон`, `Email`, `ИНН`, `СНИЛС`, `Карта`, `Счёт`, `Паспорт`, `Адрес`, `Организация`, `IP`, `Термин`; в колонке префикс можно переименовать (например, «Клиент»). Токен должен ловиться регуляркой однозначно: `Персона_0017` не должен совпадать с частью `Персона_00170`.
- **Фейк**: Faker `ru_RU` с детерминированным seed = HMAC(секрет сессии/проекта, нормализованное значение). Сохранять структуру: 3 слова → 3 слова, «Иванов И.И.» → «Смирнов А.П.», пол по отчеству или имени. Фейковый ИНН/СНИЛС/карта имеют **верную** контрольную сумму, телефон — тот же формат записи. Фейк не должен совпадать ни с одним исходным значением и ни с другим фейком этого типа (при совпадении — перегенерировать), иначе сломается размаскировка.
- **Хеш**: HMAC-SHA256(секрет, нормализованное значение), первые 10 hex-символов. Без секрета нельзя: телефоны и ИНН перебираются полным перебором за минуты.
- **Сдвиг дат и масштабирование**: одно случайное значение на колонку (или на весь файл — выбор в интерфейсе), чтобы сохранить интервалы и пропорции. Параметр хранится в таблице соответствий. Интерфейс предупреждает: сдвиг ломает дни недели и сезонность, а из одной известной пары «исходник — результат» параметр вычисляется.

**Интерфейс маскировщика:**

```python
class Masker(Protocol):
    name: str
    reversible: bool
    supports: set[EntityType]
    def mask(self, value: CellValue, entity: EntityType, ctx: MaskContext) -> CellValue: ...
    # ctx даёт доступ к MappingStore: get_or_create(entity, normalized) -> masked
```

**Таблица соответствий (`.dmmap`)**

- Содержимое: JSON `{version, created_at, project, entries: [{entity, original, masked, method}], date_shifts, scale_factors}` → сжатие → шифрование.
- Шифрование: AES-256-GCM; ключ из пароля через scrypt (`n=2^17, r=8, p=1`, соль 16 байт). Заголовок файла: магические байты `DMMAP1`, соль, nonce.
- Неверный пароль → понятная ошибка «Неверный пароль или файл повреждён», без падения.
- Проект хранится в том же формате и накапливает записи. При записи — атомарно (во временный файл, затем переименование), чтобы сбой не испортил соответствия.

**Размаскировка**

1. Псевдонимы и хеши ищутся регуляркой по формату токена и заменяются по словарю. Токен, которого нет в словаре, остаётся и попадает в отчёт.
2. Фейки заменяются как строки: сначала самые длинные, с учётом границ слов.
3. Даты и числа восстанавливаются только в XLSX/CSV в тех же колонках (по заголовку). В произвольном тексте нет: нельзя надёжно понять, какое число было замаскировано. Это пишется в отчёте.
4. JSON разбирается и обходится по строковым значениям, потому что кириллица там часто закодирована как `И...`. В HTML токены ищутся и в исходном тексте, и в виде HTML-сущностей.
5. Отчёт: сколько токенов найдено и заменено, сколько осталось неизвестных.

## 10. API и формат конфигурации

Все эндпоинты под `/api`, требуют токен и отвечают JSON (кроме скачивания). Ошибки в едином формате `{"error": {"code": "...", "message": "текст на русском без данных из файла"}}`.

| Метод и путь | Что делает |
| --- | --- |
| `POST /api/files` (multipart) | Загрузка файла → `file_id`, список листов, параметры CSV, риски |
| `GET /api/files/{id}/sheets/{sheet}/preview?header_row=1&limit=200` | Заголовки + строки для предпросмотра |
| `POST /api/files/{id}/suggest` | Автоподсказки по всем листам (тело: категории, `header_row` по листам) |
| `POST /api/files/{id}/dry-run` | Конфиг → «до/после» для первых 50 строк + сводка; ничего не сохраняет |
| `POST /api/files/{id}/mask` | Конфиг + пароль → `job_id` |
| `GET /api/jobs/{job_id}` | Статус, процент, список готовых артефактов |
| `GET /api/jobs/{job_id}/download/{masked\|mapping\|report_json\|report_html}` | Скачивание |
| `POST /api/unmask` (multipart) | Файл + `.dmmap` или `project_id` + пароль → `job_id` |
| `GET/POST/DELETE /api/projects` | Список, создание, удаление проектов |
| `GET/POST /api/templates` | Шаблоны настроек (правила «заголовок → тип + способ»; данных не содержат) |
| `DELETE /api/session` | Удалить все файлы сессии |
| `GET /api/health` | Версия, статус (без токена недоступен) |

**Пример конфигурации маскирования** (описывается Pydantic-моделью `MaskConfig`):

```json
{
  "categories": {"personal": true, "financial": true, "commercial": false},
  "consistency_scope": "file",
  "project_id": null,
  "sheets": {
    "Клиенты": {
      "header_row": 1,
      "columns": {
        "B": {"entity": "PERSON", "method": "pseudonym", "params": {"prefix": "Клиент"}},
        "C": {"entity": "PHONE",  "method": "partial",   "params": {"keep_last": 4}},
        "F": {"entity": "FREE_TEXT", "method": "pseudonym"},
        "H": {"entity": "AMOUNT", "method": "scale",     "params": {"scope": "column"}}
      },
      "scan_above_header": true
    }
  },
  "custom_terms": ["Ромашка", "Проект Альфа"],
  "sanitize": {"metadata": true, "comments": "remove", "hidden_sheets": "keep", "pivot_cache": "remove", "images": "keep"},
  "save_mapping": true
}
```

Колонки адресуются буквой (для CSV — номером), потому что заголовки бывают пустыми или повторяются. В шаблонах — наоборот, по тексту заголовка, чтобы шаблон пережил перестановку колонок. Недопустимая пара «тип + способ» (например, сдвиг дат для email) → `422` с понятным сообщением.

Для автоматизации и будущего хука Claude Code нужен ещё CLI на том же ядре: `datamask mask input.xlsx --config cfg.json --out out.xlsx --mapping out.dmmap` (пароль из переменной окружения `DATAMASK_PASSWORD` или интерактивного ввода, никогда не аргументом командной строки) и `datamask unmask`.

## 11. Критерии приёмки и тесты

Версия 1 принята, когда все пункты ниже проверены автотестами (кроме помеченных «вручную») и тесты запускаются с запретом сети (`pytest --disable-socket --allow-hosts=127.0.0.1`).

| # | Критерий | Как проверяется |
| --- | --- | --- |
| A1 | Одно и то же значение получает один псевдоним во всех колонках и листах файла; разные значения — разные | Фикстура с 3 листами и повторяющимися людьми; число уникальных до = после |
| A2 | `8 (912) 123-45-67`, `+7 912 1234567`, `89121234567` → один псевдоним; «Иванов Иван» и «иванов  иван» → один | Юнит-тесты нормализации |
| A3 | ИНН/СНИЛС/ОГРН/карта с неверной контрольной суммой не распознаются; с верной — распознаются | Наборы верных и испорченных номеров + `hypothesis`: случайные строки цифр распознаются не чаще, чем позволяет контрольная сумма |
| A4 | На синтетическом наборе из 20 таблиц автоподсказки находят ≥ 95% колонок с ПДн и дают ≤ 5% ложных подсказок | `scripts/make_fixtures.py` генерирует таблицы с разметкой; тест считает полноту и точность |
| A5 | Форматирование сохранено: стили ячеек, ширины колонок, объединения, форматы чисел, формулы и значения немаскируемых ячеек | Поклеточное сравнение исходника и результата через openpyxl |
| A6 | Результат открывается без ошибок | Авто: `soffice --headless --convert-to csv` на результате (если LibreOffice установлен); вручную: Excel на macOS |
| A7 | Числа остаются числами, даты датами при сдвиге, масштабировании и шуме; в CSV `007` не превращается в `7` | Проверка типов ячеек |
| A8 | Круговая проверка: маскирование обратимыми способами → размаскировка даёт значения, равные исходным (для масштаба — с точностью до округления) | Тест на каждом обратимом способе и формате |
| A9 | Размаскировка HTML и JSON, в которых псевдонимы встречаются внутри текста, в `\u`-экранировании и в HTML-сущностях; `Персона_0017` не задевает `Персона_00170` | Фикстуры-«дашборды» |
| A10 | Фейки детерминированы в пределах проекта, не совпадают с исходниками, фейковые ИНН/СНИЛС/карты проходят проверку контрольной суммы | Юнит-тесты |
| A11 | Метаданные (автор, «кто изменил», компания) очищены; кэш сводных удалён; примечания удалены при настройке `remove` | Распаковка результата как ZIP и поиск исходных значений во **всех** XML-файлах |
| A12 | В замаскированном файле нет ни одного исходного значения из выбранных колонок (в том числе в sharedStrings) | Тот же ZIP-поиск |
| A13 | Сервер недоступен по IP машины в локальной сети; запрос без токена → `401`; чужой `Host` → `400`; есть CSP-заголовок, нет CORS-заголовков | Интеграционные тесты API |
| A14 | В логах, отчётах и сообщениях об ошибках нет исходных значений и имён файлов | Прогон полного сценария на фикстуре с уникальными маркерами (`ЗАМЕТКА_7f3a…`) и поиск маркеров в логах и отчётах |
| A15 | Все тесты зелёные с запретом сети; собранный фронтенд не содержит абсолютных URL `http(s)://` кроме документационных ссылок | `pytest-socket` + grep по `frontend/dist` |
| A16 | Неверный пароль к `.dmmap` → понятная ошибка; файл с испорченным байтом → ошибка, а не мусор; в папке данных нет незашифрованных соответствий | Юнит-тесты + поиск исходных значений во всех файлах папки данных |
| A17 | После «Очистить сессию» и после штатного выхода временная папка сессии пуста | Интеграционный тест |
| A18 | Файл 100 тыс. строк × 10 колонок (5 маскируемых) обрабатывается за ≤ 60 с на MacBook с Apple M1; предпросмотр открывается за ≤ 3 с | Бенчмарк-тест с меткой `slow` (не в каждом прогоне) |
| A19 | Полный сценарий в браузере: загрузка → подсказки → настройка → «до/после» → скачивание → размаскировка | Вручную по чек-листу в README (по желанию — Playwright) |

## 12. Этапы разработки для Claude Code

Восемь этапов идут по порядку, каждый заканчивается работающим состоянием, зелёными тестами и коммитом. После каждого этапа — короткий отчёт пользователю: что сделано, что проверено, какие решения приняты самостоятельно.

1. **M0. Каркас.** Репозиторий по структуре из раздела 5, `pyproject.toml`, `uv.lock`, ruff/mypy/pytest, Vite-проект. FastAPI отдаёт собранный фронтенд. `scripts/run.sh` запускает сервер и открывает браузер. `CLAUDE.md` с правилами из раздела 1.
2. **M1. Безопасность сервера.** Всё из раздела 4 «Сеть»: привязка к 127.0.0.1, токен, проверка Host, CSP, сессионная папка и её очистка, логи без данных. Делается до работы с файлами, а не после. Тесты A13, A15, A17.
3. **M2. Чтение файлов и предпросмотр.** Адаптеры XLSX и CSV (чтение, листы, предпросмотр, автоопределение строки заголовка, риски), эндпоинты загрузки и предпросмотра. `scripts/make_fixtures.py` с размеченными синтетическими таблицами (в том числе «грязными»: шапка отчёта над заголовком, скрытые листы, объединённые ячейки, сводная, примечания, CSV в Windows-1251 с `;`).
4. **M3. Распознаватели и подсказки.** Валидаторы контрольных сумм, регулярки, словари заголовков, алгоритм подсказок, поиск в свободном тексте, свой словарь, эндпоинт `suggest`. Тесты A3, A4.
5. **M4. Маскирование и запись.** Все маскировщики, нормализация, `MappingStore`, шифрование `.dmmap`, запись XLSX/CSV с сохранением форматирования, очистка (sanitize), отчёт, `dry-run`, `mask`, фоновые задачи, CLI `datamask mask`. Тесты A1, A2, A5–A7, A10–A12, A14, A16, A18.
6. **M5. Интерфейс.** Экраны 1–4 из раздела 6. Приоритет — понятность для человека без технического бэкграунда: никаких внутренних кодов типов на экране, все подписи на русском, подсказки объясняют «почему».
7. **M6. Размаскировка, проекты, шаблоны.** Экраны 5–6, эндпоинты, CLI `datamask unmask`. Тесты A8, A9.
8. **M7. Финальная проверка.** Прогон всех тестов с запретом сети, бенчмарк A18, README с установкой в 3 команды и чек-листом ручной проверки A19. Отдельным агентом, не видевшим кода, — ревью безопасности по разделам 4 и 7: искать любой путь, которым исходное значение может попасть в результат, лог или сеть.
