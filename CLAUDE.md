# datamask — правила для Claude Code

Полное ТЗ: `SPEC.md`. Кратко:

1. Работать строго по этапам из SPEC §12. Этап закончен, когда все его тесты зелёные и сделан коммит. После этапа — короткий отчёт: что сделано, что проверено, какие решения приняты самостоятельно.
2. Не добавлять зависимости, которые ходят в сеть во время работы приложения (телеметрия, CDN, загрузка моделей, проверка обновлений).
3. Никогда не писать значения ячеек и имена загруженных файлов в логи, ошибки и отчёты. Только типы, количества, имена колонок/листов, `file_id`.
4. В репозитории только синтетические данные (Faker `ru_RU`, `scripts/make_fixtures.py`).
5. Неясное или противоречивое требование — остановиться и спросить.
6. `core/`, `detectors/`, `maskers/` не знают о форматах файлов и HTTP. Новые форматы — файл в `formats/`, новые распознаватели — файл в `detectors/`.

## Команды

- Тесты (сеть запрещена через addopts): `uv run pytest`; бенчмарк A18: `uv run pytest -m slow -s`
- Линтеры: `uv run ruff check . && uv run ruff format --check . && uv run mypy`
- Фронт: `cd frontend && npm run build`
- Фикстуры (синтетические, генерируются и в тестах автоматически): `uv run python scripts/make_fixtures.py`
- Запуск: `scripts/run.sh` (флаги: `--port N`, `--no-browser`)
